# Routes & screens

Main application routes live in `src/app`. The dashboard sidebar is generated from `src/configs/navigation/menuItems.tsx` and depends on the current user's CASL ability.

## Public routes

| URL | Screen |
| --- | --- |
| `/` | Landing page |
| `/login` | Login |
| `/register` | Register |

`AuthContext` treats these routes as public and skips `/api/users/v1/me` during initialization.

## Dashboard routes

| URL | Role |

## Add a new screen

1. Create `page.tsx` under `src/app/(dashboard)/...`.
2. Put large page-specific components in a sibling `_components` folder.
3. Add endpoints to `src/services/endpoints.ts` if the screen needs new APIs.
4. Add a service method under `src/services`.
5. Add permission subject/action if the route needs access control.
6. Update `ROUTE_ACCESS` in `src/configs/permissions/routeAccess.ts`.
7. Add a sidebar item in `src/configs/navigation/menuItems.tsx` if needed.
8. Update this documentation.

## Route component convention

Components used by a single page should live in that route's `_components` folder. Components reused by several modules should move to `src/components/shared`.
